# core-human-knowledge Constitution

## Core Principles

### I. Knowledge-Base Integrity & Inviolable Source (NON-NEGOTIABLE)
- Material in `raw/` represents the original source of truth and must **NEVER** be deleted, overwritten, or modified.
- All curated knowledge is transformed into canonical categories (`guides/`, `processes/`, `sessions/`).

### II. Canonical Dual Deliverables (MD + SVG)
- Every practical guide added to `guides/` must have a matching self-explanatory SVG diagram sharing the exact same basename (`NN-TIPO-tema.md` and `NN-TIPO-tema.svg`).
- Visual grammar is mandatory: 1200 px canvas, COIIAOC v2 color tokens, Segoe UI / Consolas typography, and self-contained comprehension (the diagram must be readable without opening the Markdown file).

### III. Stable Consecutive Numbering
- Categorized guides use stable, two-digit consecutive prefixes (`01`, `02`, `03`...).
- Numbers are historical identifiers and must never be reused or re-indexed.

### IV. Spec-Driven & Autonomous Execution
- Work is structured via the SpecKit lifecycle: Constitution ➔ Specify ➔ Clarify ➔ Plan ➔ Tasks ➔ Analyze.
- The agent acts autonomously without requesting confirmation for routine cataloging, formatting, and diagramming, prompting the user only upon genuine category ambiguity or destructive operations.

### V. Multi-Agent & Antigravity Compatibility
- Project instructions (`AGENTS.md`, `CLAUDE.md`) remain synchronized.
- Native tool execution on Windows / PowerShell, UTF-8 without BOM, and clickable `file:///` URI schemas.

## Quality Gates & Verification
- No task is marked complete without verifying that the `.md` and `.svg` pair is present and valid.
- Table of contents in `README.md` must be updated on every new guide addition.

## Governance
This constitution governs agentic workflows and specification-driven development in `core-human-knowledge`. Amendments must maintain backwards compatibility with existing guides and diagrams.
